# v3.4 — Findings Have Outcomes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The gate loop converges. `--stamp <reviewer> --report <file>`
reads the reviewer's reply; its findings get IDs in the stamp file; a
re-review is handed the open ones and answers each by ID; a
`[pre-existing]` finding isn't held open; a loop past
`reviewGate.maxRounds` is told to stop and ask. Nothing new blocks a
commit, and nothing depends on a harness.

**Architecture:**
- `mechanisms/hooks/review-report.mjs` (new, pure, no git): the verdict and
  finding parse of a reviewer's reply.
- `mechanisms/hooks/added-lines.mjs` (new): `addedLines` and `diffPath`,
  moved out of `convention-lint.mjs` so the gate can import them.
- `review-gate.mjs`: `--report` on `--stamp`; reviews and findings in the
  stamp file (still version 2); the re-review list, one stamp line per
  reviewer, and the round warning in the block message; the triage note by
  finding ID; v3.6's comment carry checks for open findings.
- Text: the six framework reviewers and the domain template gain one
  report step; `SDD.md` §3/§4, the ledger template,
  `docs/limitations.md` and `config.example.json` gain the outcome words,
  the `--report` step and `maxRounds`.

**Tech Stack:** Node (floor 22, no API newer than Node 18's), ES modules,
zero dependencies, the git CLI, `node:test`.

**Spec:** `docs/specs/v3.4.md` (Decisions 1–5, Clarify 1–14, AC1–AC9),
built on `docs/specs/v3.6.md`.

## Built on v3.6

v3.4 is built only after v3.6 has landed, and only on the owner's yes.
v3.6's plan wasn't written when this one was, so this plan assumes v3.6 as
its spec states it (`3ee431a`). **Task 1 checks each assumption against the
merged v3.6 code**; where one doesn't hold, the ledger records it and the
task that depends on it adapts.

- **B1 — No harness review gate** (v3.6 Decision 1). The block message
  prints only from `--pre-commit` and `--check`; `blockMessage` has no
  `mode` parameter and no hooks-mode text. The pre-commit's message names
  `--repo <its repo>` in the stamp command; v3.4's per-reviewer stamp lines
  keep it.
- **B2 — No completion stamps** (v3.6 Decision 2). `parseVerdict`,
  `subagentHook`, `readTranscript`, `stampingMode`, the `refused` record
  and `model-id.mjs` are gone; stamp entries hold `key` and `at`.
  `triageNote`'s `e.issues` read (`review-gate.mjs:219`) is dead or gone.
  v3.4 restores the verdict parse in `review-report.mjs` from
  `git show 3cf89af:mechanisms/hooks/review-gate.mjs` (`parseVerdict`,
  `:759`) and replaces `triageNote`.
- **B3 — Work-tree keys** (v3.6 Decision 2). `--stamp` keys a routed file
  from the index or the work tree, as `git add` would. This plan calls the
  resulting `Map<path, key>` of the change `changeKeys()`; use whatever
  v3.6 names it, and its rule for a file with two keys (v3.6 Clarify,
  open). The reviewed blob may not be in the object store; Task 5 writes
  it.
- **B4 — The comment carry** (v3.6 Decision 3). `judge()` decides in one
  place whether R's stamp on F carries across a comment-only change, with a
  "no open issues" condition that v3.6 can't yet evaluate. Task 8 makes it
  "R has no open `❌` citing F".
- **B5 — `SDD.md` §4 steps 3–4 rewritten** (v3.6 Scope): completion-stamp
  and harness-gate sentences gone, about 900 bytes freed; one call can
  stage, stamp and commit.
- **B6 — The reviewers** (v3.6 Decision 2, Scope). Their input is `git diff
  HEAD`, their report blocks are 3.3.2's (`eca0a4f`, on main), and
  gate-reviewer's check 5 no longer says "the completion stamp parses".
- **B7 — Tests.** `review-stamp.selftest.mjs` and
  `review-gate.shapes.selftest.mjs` are deleted; `review-gate.selftest.mjs`
  tests `--pre-commit`, `--check` and `--stamp` only.
- **B8 — Config.** `reviewGate.stamping`, `reviewerModels` and `exclude`
  are gone and reported as obsolete; `reviewGate.commentReviewer` is new.
  `maxRounds` isn't added to `ssdd-config.mjs` (Clarify 8).
- **B9 — Version.** v3.6 ships as 3.6.0; this is 3.7.0 (Clarify 14).

## Global Constraints

- Zero npm dependencies; nothing newer than Node 18's APIs.
- Tests are `*.selftest.mjs`; the suite is
  `node --test mechanisms/hooks/*.selftest.mjs bin/*.selftest.mjs packs/*/*.selftest.mjs`.
  On macOS compare temp paths through `realpathSync`.
- The stamp file stays `.git/ssdd-review-stamp.json`, `version: 2`, key
  `srcMode:srcBlob→dstMode:dstBlob`; new fields only (Clarify 7).
- **Nothing new blocks.** No exit code changes for a finding, a round or a
  count mismatch. `--stamp` refuses only what Decision 2 and Clarify 10
  name: no verdict, `NO DIFF`, an unreadable report, `--report` with
  several reviewers. A refusal writes nothing.
- The block message and the triage note never throw: a hand-edited
  `reviews` or `findings` entry is skipped, as `short()` echoes a bad key
  (`review-gate.mjs:302-307`).
- `--check` and `--pre-commit` stay read-only (the existing "writes
  nothing" test, `review-gate.selftest.mjs:555`).
- Never write to `~/Developer/prizma` or `~/Developer/Hatedate`. Real-data
  checks read the transcripts under `~/.claude/projects` and write only to
  the session scratchpad.
- No tag, push or PR without the owner's go-ahead. VERSION stays at
  v3.6's; the CHANGELOG section is `## [3.7.0] — unreleased`.
- `SDD.md` stays at most 11,000 bytes (`bin/repo.selftest.mjs:180`).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **A finding the parse half-reads**: a path with a space or a backtick
  inside, an absolute path in a linked worktree (repo root ≠ main
  checkout), `⚠` without U+FE0F → Task 3's table.
- **IDs under parallel stamps**: two `--stamp --report` calls racing must
  not hand out the same `F<n>`; IDs are assigned inside `updateStamp`'s
  lock → Task 4, "two stamps in parallel get distinct IDs".
- **Staleness at a partial commit**: committing a.ts but not b.ts leaves a
  review of both current through b.ts → Task 4.
- **A review closing another reviewer's finding** must not → Task 4.
- **The round reset** after a commit or a rebase (HEAD side moves) →
  Task 7.
- **`--report -` with an empty stdin** is refused, not read as CLEAN →
  Task 4.
