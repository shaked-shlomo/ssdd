# v3.6 — One Backlog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every SSDD repo keeps its remaining work, deferred review findings
included, in one `BACKLOG.md` at its root; a repo whose backlog has another
name migrates it once with `/migrate-backlog`, after the user approves the
report.

**Architecture:**
- The template is `process/templates/backlog-template.md`. `plan()` already
  installs `process/` as managed files; a new seeded entry copies the
  template to `BACKLOG.md`. `seedOne` skips it when the repo has a
  candidate file, and names the candidate instead. `install` and `update`
  both call `seedOne`, so one check covers both.
- `/migrate-backlog` is a skill, modelled on `/migrate-plans`: a report,
  the user's approval, the rename and rewrites, shell checks, one commit.
  No new script (Clarify 6).
- The shipped text names `BACKLOG.md` wherever it named the
  "requirements checklist" in one of four ways.
- SSDD's own `docs/BACKLOG.md` moves to the root by the skill's procedure,
  as its first real run.

**Tech Stack:** Node (floor 22, no API newer than Node 18's), ES modules,
zero dependencies, the git CLI, `node:test`.

**Spec:** `SPEC.md` → v3.6 (Goal, Evidence, Decisions 1–2, Open as ruled
2026-10-30, Clarify 1–11, AC1–AC9).

## Global Constraints

- **Order (owner, 2026-10-30):** v3.4, then v3.5, then this plan, then the
  prizma and Hatedate migrations. Before Task 1, merge `main` with v3.4 and
  v3.5 in, and take the finding ID format v3.5's clarify pass settled. The
  row form (Clarify 2) puts that ID inside `[]`. If v3.5 hasn't shipped,
  stop and ask.
- Zero npm dependencies. Tests are `*.selftest.mjs`; the full suite is
  `node --test bin/*.selftest.mjs mechanisms/hooks/*.selftest.mjs packs/*/*.selftest.mjs`.
  CI runs Linux; on macOS compare temp paths through `realpathSync`.
- Never write to `~/Developer/prizma` or `~/Developer/Hatedate`. Scratch
  clones live in the session scratchpad. Nothing is pushed.
- Budgets (`bin/repo.selftest.mjs`, "text budgets"): `process/SDD.md` is
  10,990 of 11,000 bytes, and the AGENTS template 44 of 45 lines. Measure
  each edit with `wc -c` / `wc -l`; Clarify 7 lists the edits that fit.
- A selftest that pins text (`bin/ssdd.selftest.mjs` "migrate-plans
  skill", "framework files"; `bin/repo.selftest.mjs` "the BACKLOG cites
  docs/limitations.md") is weakened only by a ledger ruling. Changing the
  path it reads (Task 4) isn't weakening.
- No tag, push or PR without the owner's go-ahead. VERSION stays at what
  main has; the CHANGELOG section is `## [3.6.0] — unreleased`, and VERSION
  becomes 3.6.0 in the release commit.
- Every commit passes the review gate as its block message says. Commits
  end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The ledger is `.superpowers/sdd/2026-10-30-v3-6-backlog/progress.md`.

## Review Focus

- **`update` seeds over a renamed backlog.** A repo on 3.4 with
  `docs/pre-launch-requirements.md` and no `BACKLOG.md` must get the
  candidate line on `update`, not a second backlog → Task 1, "update names
  a candidate and seeds nothing".
- **A false candidate** (`requirements.txt`, `docs/a/b-checklist.md`,
  `CHANGELOG.md`) silently stops seeding → Task 1, "not candidates".
- **`SDD.md` over budget** → Task 2, "text budgets" (target 10,980 bytes).
- **The skill rewrites a file SSDD manages**, which the next `update` then
  sees as a project edit → Task 3's procedure text, checked in Task 5 on
  prizma's `.ssdd/process/templates/task-ledger-template.md` and
  `.ssdd/reviewers/docs-sync-reviewer.md`.
- **The migration drops a line of the old file** → Clarify 6's diff, run in
  Tasks 4 and 5, output in the ledger.
- **A relative link breaks after the move** (Hatedate has 4 links to its
  file; SSDD's `docs/handovers/README.md` has 2) → `bin/repo.selftest.mjs`
  "links" in Task 4; a scratch link check in Task 5.
