# v3 Part 5 — Trimming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SSDD is only as big as what it does: the spec split per version, a
one-page README, the drift audit opt-in, a thin `/cleanup`, every skill and
instruction file held to D3, smaller templates, and Node 22 as the floor.

**Architecture:**
- Text moves, it isn't rewritten: SPEC.md's sections go to `docs/specs/`,
  the README's detail to `docs/usage.md` and `docs/limitations.md`. A new
  `bin/repo.selftest.mjs` holds the repo's own invariants (the index, links,
  citations, the Node floor, text budgets). `bin/` never ships to an
  injected repo.
- `bin/ssdd.mjs` gains optional parts (`--with drift-audit`), recorded in the
  lock's `with`, the same way packs are.
- `/cleanup` delegates the general review to the harness and keeps only
  what SSDD adds: the routed reviewers, the merge, the approval.

**Tech Stack:** Node (floor 22, nothing newer than Node 18's APIs used here),
ES modules, zero dependencies, the git CLI, `node:test`.

**Spec:** `SPEC.md` → v3 → Part 5 (Goal, Evidence, Decisions 1–7, Open,
Clarify 44–51, AC39–AC47). After Task 1 that's `docs/specs/v3.md` → Part 5.

## Global Constraints

- Zero npm dependencies. The floor is Node 22, but no API newer than Node
  18's lands in this plan (Clarify 50: a repo on Node 20 keeps working).
- Tests are `*.selftest.mjs`; the suite is
  `node --test mechanisms/hooks/*.selftest.mjs bin/*.selftest.mjs packs/*/*.selftest.mjs`.
  CI runs Linux; on macOS compare temp paths through `realpathSync`.
- Never write to `~/Developer/prizma` or `~/Developer/Hatedate`. Scratch
  installs live in the session scratchpad.
- No tag, push or PR without the owner's go-ahead. VERSION stays `3.2.1`;
  the CHANGELOG section is `## [3.3.0] — unreleased`.
- Moved text keeps its words. A trim cuts how-to-reason prose and restated
  procedure; it keeps facts, commands, scripts, gotchas, formats and
  one-line reasons (Clarify 48).
- A selftest that pins text (`bin/ssdd.selftest.mjs` "ssdd.mdc and the
  AGENTS template carry the run-the-script line", "docs name the paths
  setting", "migrate-plans skill"; `bin/skills-audit.selftest.mjs`
  "SKILL.md") is weakened only by a ledger ruling.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **A repo installed before 3.3 with the drift audit, updated with no
  flag,** keeps it; the files must not be read as removed upstream → Task 3,
  "update keeps drift-audit for a lock from before --with".
- **A project-edited `docs-drift-audit/SKILL.md` under `update --with none`**
  (its domain list filled in) is kept with a warning, never deleted → Task 3,
  "update --with none keeps an edited file".
- **A project's own dangling link in `.claude/skills/`** (not SSDD's
  `../../.agents/skills/<name>` shape) is left alone by the prune → Task 3,
  "update --with none removes the files and the dangling link".
- **Moving text drops a paragraph** (SPEC.md → `docs/specs/`, README →
  `docs/`) → the one-off checks in Task 1 Step 4 and Task 7 Step 4, output
  in the ledger.
- **A relative link inside moved text breaks** (`docs/specs/` is two levels
  down) → Task 1, "every relative link resolves", re-run in Task 7.
