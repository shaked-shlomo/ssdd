# v3.6 — the gate lives in git

**Date:** 2026-10-30 · **Status:** draft (clarify pass not run) · **Branch:** none yet

## Goal

SSDD gets smaller and stays a framework for any harness. The review gate is
the git pre-commit, which every harness and every human already meets. The
harness hooks keep only what holds that pre-commit in the loop, what guards
an action that goes out (production, a force push), and two conveniences.
Every setting no project changed, every hook only one harness can run, and
every block on a mistake that can be undone locally either goes or becomes
a warning.

The owner's rules for this release:
- **Hard blocks only where a mistake is irreversible or outward-facing;**
  everything else warns or goes (2026-10-23).
- **Harness-neutral** (2026-10-30): "it should still be a general framework
  that fits any harness chosen", Cursor included. A harness hook may make a
  check earlier or cheaper; it never adds a rule of its own.
- **Simple and effective, not existing just to exist** (2026-10-30): a
  setting or mechanism stays only if a project used it or an incident
  needed it.

The quick fixes from the 2026-10-23 audit ship as 3.3.2, not here.

## Evidence

All checked 2026-10-30 against this branch (`7d2a6a2`), prizma and Hatedate
read-only, and the Claude Code transcripts under `~/.claude/projects` (142
project folders).

**1. Two layers run the review gate, and the harness one is most of the
code.**
- The pre-commit runs `review-gate.mjs --pre-commit`
  (`mechanisms/hooks/pre-commit:22`), which judges the index git is
  committing (`review-gate.mjs:466-469`). `install` and `update` arm it when
  they can (`armHook`, `bin/ssdd.mjs:347-354`).
- Probed in a scratch repo on git 2.54.0, with a pre-commit that prints
  `git diff --staged --name-only`: `commit -am` showed both modified files,
  `git add c.txt && git commit` showed `c.txt`, and `commit -m z b.txt`
  showed `b.txt`.
- The harness mode (`review-gate.mjs:489-750`) runs *before* the command,
  so it reads the index as it was. To make up for that, it:
  - walks `cd` / `-C` / `pushd` to find the target repo (`walk`,
    `:548-580`) and denies a call that commits to two repos (`:586`);
  - refuses staging chained before a commit unless every path is a visible,
    unrouted `git add` (`BESIDE_ADD`, `chainedAddReason`, `:620-693`);
  - refuses `commit -a/-i/-o` and `commit <pathspec>` (`:694-729`).
  It carries a 401-line test file (`review-gate.shapes.selftest.mjs`), an
  `if` filter (`docs/specs/v2.6.md` Clarify 9), and `commandStart`,
  `gitInvocation` and `isCommit` in `git-cmd.mjs` (`:35`, `:97-124`), which
  nothing else imports.
- **Its cost:** Hatedate's transcripts hold 209 calls that chain staging
  with a commit, and 78 add a routed file, so each is refused today
  (`docs/specs/v3.md:1193-1199`). Before v3 Part 3's unrouted exception, 12
  of Hatedate's 14 blocks were docs-only commits or scratch repos
  (`v3.md:1049-1051`).
- **The incident the chained-add rule answered had no pre-commit gate.**
  Hatedate's "2026-08-10 wip-commit incident" ("a chained 'git add ... &&
  git commit' with a clean index passed the empty-staged early-exit and
  committed un-reviewed", Hatedate `50207a0b`) was ported by v2.1
  (`v2.1.md:16-23`) and kept by v2.6 (Clarify 1). Hatedate's gate was
  `.claude/hooks/review-gate.mjs`, a "PreToolUse(Bash) review gate" with no
  pre-commit mode. Its `.githooks/pre-commit` (163 lines at `50207a0b`)
  checks untracked files and asset imports and has never run a review gate
  (`git log -S'review-gate' -- .githooks/pre-commit` is empty). An armed
  SSDD pre-commit closes that shape on its own.

**2. Completion stamps are Claude-only, opt-in, and unused.**
- They take SubagentStart / SubagentStop wiring
  (`adapters/claude-code/settings-hooks.json:62-81`), dispatch files under a
  lock, a transcript reader with a desktop-app special case
  (`readTranscript`, `review-gate.mjs:791-807`), a verdict parser, a model
  allow-list (`reviewerModels`, `:849`; `model-id.mjs`), and a git-guard
  rule for `stamping: "hooks"` (`git-guard.mjs:120-126`). The code is
  `review-gate.mjs:755-868`; the tests, `review-stamp.selftest.mjs` (351
  lines).
- Cursor has no subagent hooks, so Cursor repos are manual anyway
  (`docs/specs/v2.3.md`, Decision 5).
- prizma's config sets neither `stamping` nor `reviewerModels`; Hatedate has
  no `.ssdd/config.json`. v2.6 kept `reviewerModels` with "Revisit if no
  project turns it on" (Clarify 7).
- Manual stamping's misuse: 4 of 449 stamps, none since 2026-09-08
  (`docs/specs/v3.4.md`, Open 1).
- They fail silently: SubagentStart snapshots staged files only
  (`:822-826`), so a reviewer dispatched before `git add` stamps nothing,
  and the hook's stderr reaches no one (`:833-834`).

**3. A review run before `git add` counts for nothing, on any harness.**
- `--stamp` refuses a file that isn't staged (`review-gate.mjs:405-410`,
  `:417`).
- Every reviewer's default input is `git diff --staged` ("How to run" step
  1 in `reviewers/*.md`, e.g. `docs-sync-reviewer.md:34`).

**4. Any blob change voids every reviewer's stamp on the file.**
- `judge()` owes a file to each routed reviewer whose stamp key isn't the
  staged key (`review-gate.mjs:249`). The key is the blob pair
  (`stagedChanges`, `:121-129`), so a comment edit is a new key, and every
  routed reviewer re-runs on the delta (`deltaFor`, `:270`).
- prizma plan 35 task 3 was "comment/prose only" and ran five rounds
  (`prizma/.ssdd/ledgers/35-last-published-at-writer-ledger.md:16`).
- **The same ledger line cuts the other way.** Those rounds found real
  wrong claims: resilience found two more instances of the class, a round-3
  fix "carried a wrong premise" that resilience's next round caught, and
  bias-semantics and the task reviewer each found one. None came from
  docs-sync, whose contract is doc couplings, not whether a comment is true
  (`reviewers/docs-sync-reviewer.md:12-41`).
- Repeats cost in general: in Hatedate, 31% of 391 reviewer runs were
  repeats (`docs/specs/v3.md:1045-1046`), in its whole-diff-stamp era.
- The friction is comment edits in routed source. prizma's docs-sync route
  covers `^src/`, `^scripts/`, `^supabase/`, `package.json` and
  `.github/workflows/`, not `docs/`.

**5. git-guard blocks things that can be undone, and checks shapes no agent
used.**
- It blocks `git add -A` / `.` / `--all` and `git commit --amend`
  (`git-guard.mjs:129-142`). Both are local and reversible: an amend
  reaches the remote only through a force push, which the default
  `extraRules` entry blocks (`mechanisms/config.example.json`, `gitGuard`).
- A PreToolUse `Edit|Write|MultiEdit|NotebookEdit` entry
  (`settings-hooks.json:41-49`) runs git-guard on every file edit, to deny
  the file tools on `.git/ssdd-review-*` (`git-guard.mjs:58-64`). Across the
  142 transcript folders: no Edit/Write/MultiEdit/NotebookEdit call on a
  `review-stamp` or `review-dispatch` path (the one hit is SSDD's own
  `review-stamp.test.mjs`), and the deny message never appears. The four
  self-stamps were `--stamp` calls (`git show 68a02e9:docs/specs/v3.4.md`,
  lines 119-153).
- `core.hooksPath` detection covers the `GIT_CONFIG_PARAMETERS` /
  `GIT_CONFIG_KEY_<n>` env forms (`viaEnv`, `:112`), abbreviated write
  options such as `--unset-a` (`isWriteOption`, `:87-89`) and shell
  expansion before the key (`configWrites`, `:93-105`). The env forms
  appear in no prizma or Hatedate transcript, only in SSDD sessions
  searching for them; Hatedate's hooks never had them (`git log --all
  -G'GIT_CONFIG'` is empty there); they arrived in SSDD's v2.1 scope
  (`v2.1.md:55-56`). The abbreviation and expansion rules came "From the
  second automated review" (`35dbb04`).
- The threat-model rule they fail: "A new evasion shape is out of scope
  unless an agent was seen using it in a real project" (`docs/BACKLOG.md`;
  `v2.6.md` Clarify 3).

**6. A lint match fails the commit.** The pre-commit runs `convention-lint
--staged` under `set -e` (`pre-commit:8`), and `--staged` exits 1 on any
finding (`convention-lint.mjs:149-150`). The lint's own header calls it
"Advisory" (`:3`). A regex for a hardcoded color stops a commit.

**7. Settings no project changed.**
- prizma's config sets `routing`, `reviewGate.maxRoutedFiles` (measured on
  its history), `gitGuard` and one `lint` rule. Its `gitGuard` toggles are
  `blockBulkAdd`, `blockNoVerify` and `blockAmend`, all `true`.
- Never set by a project: `reviewGate.stamping`, `reviewerModels`,
  `reviewGate.exclude`, `preCommit.blockUntracked` (an opt-in block; the
  default is a warning), `gitGuard.blockHooksPath`, and
  `modelReview.generation`.
- `reviewGate.exclude` is a second way to say a route's own `exclude`
  (`review-gate.mjs:98-112`).
- `modelReview.generation` drives one session-view line
  (`work-state.mjs:354-359`), read from the harness payload's model, so only
  a harness that sends one sees it.
- `paths` isn't set by prizma either, but Hatedate keeps its plans in
  `.claude/plans`, so its migration may need it.

**8. New hook wiring never reaches an installed repo, and nothing says so.**
- `.claude/settings.json` is seeded: `update` "never touches them and
  prints how their templates changed instead" (`bin/ssdd.mjs:31-33`;
  `seedOne`, `:295-298`; the diff, `:569-579`).
- prizma's and Hatedate's `.claude/settings.json` wire only `PreToolUse`
  and `PostToolUse`, no `SessionStart`. Both are pre-migration.
- Cursor's `.cursor/hooks.json` is managed (`bin/ssdd.mjs:225`) and
  three-way merged by `update`, so the gap is Claude Code's seeded file.
- `status` warns about a broken config and a dormant pre-commit
  (`gateWarnings`, `bin/ssdd.mjs:700-714`). The session view doesn't
  mention a dormant pre-commit (`work-state.mjs:350-353`); today the harness
  gate does, on every commit (`review-gate.mjs:737-742`).

## Decisions

1. **The pre-commit is the review gate; the harness review gate goes.**
   - `review-gate.mjs`'s harness mode is removed (`:489-750`), with its
     PreToolUse entry in `settings-hooks.json` and its
     `beforeShellExecution` entry in `adapters/cursor/hooks.json`. Its
     shape checks, its repo walk and the `if` filter go with it, and so do
     `commandStart`, `gitInvocation` and `isCommit` in `git-cmd.mjs`.
   - Staging, stamping and committing can share one call on any harness.
     git runs the pre-commit on the index it really commits, in the repo it
     really commits to, so a worktree, a `cd` or `-a` is judged right.
   - `--pre-commit`'s block message names `--repo <its repo>` in the stamp
     command it prints, since it can't know the agent's cwd.
   - `SSDD_REVIEW_SKIP=1 git commit …` still works: the variable reaches the
     pre-commit.
   - A dormant pre-commit means no gate. `install` and `update` arm it as
     today; `status` and the session view (Decision 7) say when it's off.
2. **One way to stamp: `--stamp`, and it accepts a review run before
   `git add`.**
   - Completion stamps, `reviewGate.stamping` and `reviewerModels` are
     removed: the SubagentStart / SubagentStop entries, `subagentHook`,
     `readTranscript`, `parseVerdict`, `modelAllowed`, `model-id.mjs`, the
     dispatch files, the `refused` record, and git-guard's hooks-mode rule.
   - A stamp may name a routed file's work-tree content. An unstaged or
     untracked (not ignored) file is keyed as `git add` would key it:
     `srcMode:srcBlob` from `git ls-tree HEAD`, `dstMode:dstBlob` from its
     file mode and `git hash-object --path`. A later `git add` of the same
     content stages the same key, so the stamp holds. `--stamp` refuses
     only a file that's neither changed nor routed.
   - The reviewer contracts' input becomes `git diff HEAD` for the routed
     files (staged and unstaged), or the range the orchestrator names.
3. **A comment-only change carries a clean stamp forward.**
   - When reviewer R's stamped blob and the staged blob of file F differ
     only in comments, R's stamp still meets the gate, provided:
     - the HEAD side and both modes are unchanged, and the stamped blob
       still exists (`deltaFor`'s `'gone'` case doesn't carry);
     - R's stamp records no open issues (with v3.4, no open finding of R's
       on F). A reviewer that flagged something on F re-reviews F: it's the
       one who can say it's fixed;
     - R isn't the comment reviewer.
   - The comment reviewer, `reviewGate.commentReviewer` (default
     `docs-sync-reviewer`), still owes F and gets the delta as today. When
     it isn't routed to F, nothing carries.
   - It's computed in `judge()`, stateless: the stamp stays on its old key
     and each judgment compares the stripped blobs again, so `--check` and
     `--pre-commit` stay read-only. The triage note says which stamps
     carried.
   - **Comment-only** means byte-equal after stripping comments, trailing
     whitespace and blank lines. Conservative:
     - Only the JS/TS family (`.js .mjs .cjs .jsx .ts .tsx .mts .cts`). Any
       other extension is never comment-only.
     - Strings, template literals and regex literals are tokenized before
       comments; anything the scanner can't classify makes the change code.
     - A comment a tool reads is code: shebang, `eslint-`, `@ts-`,
       `prettier-ignore`, `c8` / `istanbul ignore`, `/*#__PURE__*/`,
       `/// <reference`, `//# sourceMappingURL`, and JSDoc type tags in a
       `.js`-family file.
   - docs-sync's contract gains a section: on a comment-only delta, check
     each changed comment's claim against the code it describes. That's the
     class plan 35's rounds caught (Evidence 4).
4. **git-guard blocks only what keeps the pre-commit running and what goes
   out.**
   - Blocks stay for `commit -n` / `--no-verify` and the plain
     `core.hooksPath` writes: `git -c core.hooksPath=…`, and `git config`
     naming the key with a value after it or with a spelled-out write
     subcommand or option (`set`, `unset`, `--unset`, `--unset-all`,
     `--add`, `--replace-all`, `--edit`). Reads pass. `extraRules` stays,
     with the force-push rule in the example config.
   - `git add -A` / `.` / `--all` and `commit --amend` are allowed with a
     warning that says what to do instead.
   - Removed: the `Edit|Write|MultiEdit|NotebookEdit` entry and git-guard's
     file-path check (`:58-64`), the env forms, abbreviated options and the
     shell-expansion rule. Each returns with the incident that shows an
     agent using it.
   - The four `gitGuard.block*` toggles go: with two blocks left, both
     load-bearing, there's nothing to turn off.
   - `GIT_CONFIG_PARAMETERS=… git commit` turns the pre-commit off and now
     passes everything. No agent has written it; `docs/limitations.md`
     records it.
5. **Lint findings warn at commit time.** The pre-commit prints convention
   lint's findings and continues: `--staged` exits 0, or the pre-commit
   stops treating its exit as fatal. Edit-time lint (the PostToolUse /
   `afterFileEdit` hook) is unchanged; it only shows findings earlier.
6. **The config loses what no project set.**
   - Removed: `reviewGate.stamping`, `reviewGate.reviewerModels`,
     `reviewGate.exclude` (a route's own `exclude` stays),
     `preCommit.blockUntracked` (the untracked check stays a warning),
     `gitGuard.block*`, and `modelReview.generation` with its session line.
     The new-model checklist stays in README.
   - Added: `reviewGate.commentReviewer` (Decision 3).
   - A config that still has a removed key works; the key is ignored and
     `status` names it as obsolete. A config isn't broken for having one.
7. **`status` and the session view say what's off; nothing rewrites a
   project-owned file.**
   - For each installed adapter whose wiring is seeded (Claude Code's
     `.claude/settings.json`), `status` and the end of `update` list the
     template's hook entries the project lacks, with what each runs, and
     the entries the template dropped as safe to remove (Decisions 1, 2
     and 4 drop four).
   - The session view gains one line when the pre-commit is dormant, with
     the command to arm it. It replaces the harness gate's per-commit note.
   - Nothing in the gate depends on a hook event being wired: a missing one
     costs only the convenience it adds.

**What's left of the harness wiring.** Claude Code: SessionStart (the work
view), PreToolUse(Bash) git-guard and prod-guard, PreToolUse(`mcp__.*`)
prod-guard, PostToolUse(Edit|Write) convention-lint: 5 entries, from 9.
Cursor: `sessionStart`, `beforeShellExecution` git-guard and prod-guard,
`beforeMCPExecution` prod-guard, `afterFileEdit` convention-lint: 5, from 6.

**Interactions with v3.4** (unbuilt; v3.6 doesn't depend on it, but v3.4
does depend on what v3.6 removes):
- v3.4 Decision 2 parses findings at SubagentStop. With completion stamps
  gone, `--stamp --report <file>` is its only path, and v3.4's Open 1
  (`stamping: "hooks"` by default) is moot. v3.4 was revised to match on
  2026-10-30 (Open 3).
- A carried stamp isn't a review: it doesn't count as a v3.4 round and keeps
  R's findings. Since a stamp with open findings doesn't carry, a comment
  fix to R's own finding goes back to R, whose `✅ [<id>] fixed` closes it.
- v3.4's triage note and round-cap warning print from `--pre-commit`, which
  is where the gate now speaks.

## Scope

**In:**
- review-gate: harness mode and completion stamps removed; work-tree keys
  in `--stamp`; the comment-only carry in `judge()` and the triage note;
  `--repo` in the pre-commit's block message.
- A comment scanner for the JS/TS family, no dependencies, in
  `mechanisms/hooks/`. `model-id.mjs` removed; `git-cmd.mjs` loses three
  functions.
- git-guard: amend and bulk add as warnings; the file-path check, the
  hooks-mode rule, the env / abbreviation / expansion rules and the
  toggles removed; header comment updated.
- `convention-lint --staged` warns; the pre-commit continues.
- `ssdd-config.mjs`: the removed keys ignored and reported; the new key.
- `work-state.mjs`: the dormant-pre-commit line; the model-generation line
  removed.
- `bin/ssdd.mjs`: the wiring report in `status` and `update`.
- Adapters: `settings-hooks.json` loses four entries; Cursor's `hooks.json`
  loses one.
- The five framework reviewers and the domain template: input `git diff
  HEAD`. 3.3.2 rewrites their report blocks (branch
  `claude/3-3-2-process-text-e5f22e`, `eca0a4f`), so these edits start from
  that text. docs-sync's comment-claim section.
- `config.example.json`, README (threat model, the gate's layers),
  `SDD.md` §4 (one call can stage, stamp and commit; stamping before `git
  add`), `docs/limitations.md`, the selftests and CHANGELOG.

**Out:**
- Comment-only for other languages. Each needs its own scanner and the
  same "unsure is code" rule.
- Prose-only changes in a routed doc: its reviewers are routed to the prose
  on purpose.
- `paths` (Hatedate's migration may need it), `maxRoutedFiles` (measured),
  `extraRules`, `productionGuard` and the Supabase pack (outward-facing).
- prod-guard's shell reading (`shell-view.mjs`): it guards production, and
  it builds on `git-cmd`'s tokenizer rather than duplicating it.
- `/skills-audit` (never run in prizma; `docs/BACKLOG.md` → Later already
  asks to revisit it).
- The 3.3.2 quick fixes.

**Footprint:** removes about 370 lines of `review-gate.mjs` (harness mode
and completion stamps), `model-id.mjs`, about 30 lines of `git-cmd.mjs`,
about 45 lines of git-guard, two test files (752 lines) and parts of three
more, four Claude Code hook entries, one Cursor entry, and nine config keys.
Adds one scanner, one key function, one config key and two warnings. No new
hook event, no new git hook, no new block.

## Open

**Resolved by the owner, 2026-10-30:** every item below as my call: (1)
accept, (2) option (a), (3) v3.4 revised, (4) warn, (5) v3.6 before v3.4,
both before the migrations.

1. **Removing the harness gate leaves a dormant repo ungated.** Today the
   harness gate is the only gate where `core.hooksPath` isn't set (a fresh
   clone before `install`/`update`, or a user who unset it). After v3.6 the
   session view and `status` say so, and nothing blocks. My call: accept
   it. That's the owner's rule, a local commit can be undone, and the
   `prepare` script (`bin/ssdd.mjs:364-366`) arms a fresh clone on `npm
   install`.
2. **Decision 3's evidence is mixed.** Plan 35's comment-only rounds were
   costly and also caught wrong claims, from resilience, bias-semantics and
   the task reviewer. Clean stamps carrying, plus docs-sync checking comment
   claims, recovers some of that: a reviewer that was clean on F won't see
   a new wrong comment on F. Options: (a) as decided; (b) carry only for
   comment deletions and whitespace; (c) drop Decision 3. My call: (a).
3. **v3.4 needed a revision.** Its finding parse sat in a hook v3.6
   removes. Resolved (owner, 2026-10-30): v3.4 now reads findings from
   `--stamp --report`, and v3.6 is built first.
4. **Bulk add as a warning.** `git add -A` can stage a secret that a later
   push publishes, and no check stands at the push. My call: warn, since
   the agent reads the warning before it commits and the staged list is in
   the commit output; if the owner wants a push-time check, that's its own
   item.
5. **Sequencing with the migrations.** The migrations wait for v3.4 (owner,
   2026-10-22). With Open 3, v3.6 comes before v3.4, so before the
   migrations too, and each project migrates onto the smaller gate once.

## Clarify pass

*Not run.* It has to settle at least:
- The JS/TS scanner's grammar: regex-versus-division, JSX text, nested
  template literals, and the list of tool-read comments. Test it on prizma's
  and SSDD's own history: every comment-only commit it finds, and no code
  change it calls comment-only.
- Whether stripping should also ignore a comment line that only moves.
- A file both staged and edited after staging has two keys. Which one
  `--stamp` names needs a rule; `git diff HEAD` shows the reviewer the
  work-tree one.
- `git hash-object --path` applies the same clean filters as `git add`
  (autocrlf, LFS); check on a repo that uses them.
- "Armed" for the dormant line: `dormantHook` asks only whether a
  pre-commit exists where `core.hooksPath` points
  (`ssdd-config.mjs:190-212`). Hatedate's is set, present, and never ran
  the gate, so armed has to mean SSDD's pre-commit (its hash matches the
  lock's managed entry, or it runs `review-gate.mjs --pre-commit`).
- How a warning reaches the agent from a git-guard that allows: stderr with
  exit 0 on Claude Code, and the `agentMessage` field on Cursor.
- How `status` matches a hook entry the project wrapped (another path,
  extra env).
- The test files: which cases of `review-gate.shapes.selftest.mjs` and
  `review-stamp.selftest.mjs` move to `--pre-commit` and `--stamp` tests
  before the files go.
- Codex and other harnesses with no adapter: confirm they meet the
  pre-commit and the CLI only, and that nothing else differs.
- Version: 3.6.0 (MINOR): removed keys are ignored, not errors, and no
  project-owned file changes. CHANGELOG's Upgrade section lists the hook
  entries to remove.
